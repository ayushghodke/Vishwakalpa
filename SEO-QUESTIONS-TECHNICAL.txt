WHY: This is the one real fork in the road, and it gets more expensive to
change the longer we wait.

You're a Vite 7 + React 19 SPA using react-router-dom 7.13 in library mode
(plain <BrowserRouter>). Every route serves the same empty <div id="root">
plus one static <head>. Consequences:

  - Google CAN render JS, but does it on a delayed second pass. Fine for 6
    URLs. Less fine for ~40 long-tail pages that are the entire strategy.
  - AI crawlers (GPTBot, PerplexityBot, ClaudeBot) mostly DON'T execute JS.
    They get an empty div. This is a growing discovery channel and it's the
    one where a small firm can actually beat a big one.
  - Social scrapers never run JS. Your link previews are dead today regardless.
  - No per-route <head> at all — every service page currently claims the
    homepage's canonical.

RESEARCH NOTE: vite-react-ssg's own README now redirects React Router v7
users to RR7's built-in SSG. You're already on 7.13.1, so the first-party
path is available and no third-party plugin is needed.

CORRECTION — I told you earlier that React 19 hoists <title>/<meta> natively
so option B needs no library. That was WRONG and I've verified it against the
installed react-dom@19.2.4 source. React hoists title/meta but never DEDUPES
them (getResource returns null for `case "meta": case "title":` — only
rel="stylesheet" becomes a deduped resource). mountHoistable does:

    hoistableRoot.head.insertBefore(
      instance,
      "title" === type ? hoistableRoot.querySelector("head > title") : null
    );

So against the existing static tags in index.html:
  <title>       → inserted BEFORE existing → React's wins, but 2 titles in DOM
  <meta name=description> → insertBefore(…, null) = APPEND → STATIC ONE WINS
  <link canonical>        → append → TWO CANONICALS

Rendering meta in-tree does NOT override index.html. Option B therefore needs
an imperative mutation hook, not React 19 hoisting. Costed honestly below.

CORRECTION 2 — I also said the vercel.json catch-all would shadow prerendered
files. Also wrong. Vercel docs: "precedence is given to the filesystem prior
to rewrites being applied." The real traps are different (see 3.4).

 4. MAINTENANCE MODE                                               ★ BLOCKING
===============================================================================

WHY — read this one properly, it's the most urgent thing in the file:

  src/constants/config.ts:10  →  MAINTENANCE_MODE = true
  src/App.tsx:15-17           →  returns <Maintenance /> for the entire app
  vercel.json                 →  rewrites /(.*) to /index.html

So every URL returns HTTP 200 with your real title/description/canonical/
JSON-LD in the raw HTML — and then renders "We're building something great."
No noindex. No 503. Googlebot executes the JS, so the DOM it indexes is the
construction page.

This is the worst of all configurations. A 503 + Retry-After tells Google
"temporary, hold the index." A 200 tells Google "this IS the page" — so it
replaces your real content in the index with a progress bar. It also means
the HTML promises architecture content and the render delivers something
else, which is its own quality signal problem.

Also: isPreviewUnlocked() only reads window.location.search and nothing
persists it, so a hard refresh or a shared /service/... link drops back to
the maintenance page. And the token ships in the client bundle in plaintext
(the file's own comment concedes this — it's obscurity, not security).

4.1 ★ What do you want?
    [* ] Flip MAINTENANCE_MODE off now — go live, let real content index
    [ ] Keep it on, but return 503 + Retry-After + X-Robots-Tag: noindex
    [ ] Keep it on as-is (please don't, but tell me if there's a reason)
    Target launch date: ......................................................

4.2 If staying dark — now VERIFIED, and the answer is more constrained than
    I first said:

    · X-Robots-Tag: noindex — TRIVIAL, and it's the part that actually
      matters. Pure vercel.json, no function:
          { "headers": [{ "source": "/(.*)", "headers": [
              { "key": "X-Robots-Tag", "value": "noindex, nofollow" },
              { "key": "Cache-Control", "value": "no-store" } ]}]}

    · 503 + Retry-After — NOT ACHIEVABLE from static vercel.json config.
      `headers` cannot set a status code. `redirects` only does 3xx.
      `rewrites` run after the filesystem so they can't intercept /. The only
      pure-config candidate is legacy `routes` (has status + headers +
      missing, runs before the filesystem) but whether status:503 + dest
      serves a body is UNDOCUMENTED — I'd be guessing. Verify on a preview:
          curl -sI https://<preview>.vercel.app/ | head -1

    · The clean way is middleware.ts at repo root — verified: works with
      framework=other, runs before the request is processed, can return
      new Response(html, { status: 503, headers }), and next() from
      @vercel/functions lets preview traffic through.
      COSTS: fluid-compute billing per request (negligible at your traffic),
      and Vercel docs flag "Permissions Required: Routing Middleware".
